# MotionBridge UE：简历与项目讲解材料

以下内容按真实实现边界撰写。投递时选择一个主版本，不要把三套描述全部堆进同一份简历。

## 动捕动画岗位版

### 简历条目

**MotionBridge UE｜动捕动画处理与 Unreal 运行时系统**

- 自研 BVH 解析、通道解码与 FK，完成旋转顺序、骨长与逐帧世界姿势验证，并建立 Blender/FBX/UE5 Manny 重定向流水线。
- 将髋部运动拆分为地面 Root Motion 与局部骨盆动作，通过逆根变换重建验证；在 UE 中由 `CharacterMovement` 驱动胶囊，实测输入轨迹 `91.866 cm`、角色移动 `91.736 cm`。
- 实现 C++ Foot IK：脚跟/脚尖双射线、骨盆补偿、Two Bone IK、斜坡法线对齐和指数平滑；10° 斜坡鞋底最小间隙保持为正。
- 构建 UDP/WebSocket 实时姿势缓冲、插值、超时回退与自动重连；89 骨骼、69 帧回放最终局部姿势误差为 `0.000`。

### 60 秒讲解

这个项目解决的是“动捕数据如何可靠进入 UE 角色并在运行时正确播放”。我先自己实现 BVH Parser、帧解码和 FK，确保理解数据语义，再通过 Blender 和 UE IK Retargeter把动作映射到 Manny。后面重点处理了两个常见问题：第一是把髋部轨迹拆成真正推动角色胶囊的 Root Motion，避免网格自己滑；第二是用双接触点 Foot IK 处理地面贴合和斜坡朝向。最后我把离线帧做成 UDP/WebSocket 实时流，加入线程安全交接、插值缓冲、断流回退、重连和 UMG 监控。项目里重定向求解使用 UE 内置工具，但 BVH/FK、Root Motion 处理、运行时系统和 Foot IK 是我重点实现和验证的部分。

## AI 虚拟人系统岗位版

### 简历条目

**MotionBridge UE｜实时虚拟人动画数据桥接系统**

- 设计版本化 JSON 动画协议，统一承载骨骼局部姿势、Root Motion、时间戳和 BlendShape/Morph 标量通道。
- 在 UE C++ 中实现 UDP/WebSocket 双传输入口：回调线程仅入 MPSC 队列，游戏线程完成校验、时间排序、插值采样与 UObject 更新。
- 实现超时回退、首帧 root 基准重建和自动重连；强制每 50 帧断线的测试中完成 2 次恢复并持续接收。
- 以原创测试头像验证 `Smile/JawOpen/BlinkLeft/BlinkRight` 四个 Morph Target 的实时映射和平滑，并用原生 UMG 展示约 30 Hz 输入、FPS、端到端延迟与帧质量。

### 60 秒讲解

我把它做成了一个模型无关的实时虚拟人数据桥。上游可以是预录动作、动捕服务，也可以换成语音驱动模型；下游 UE 只认版本化帧协议。网络回调不会直接碰角色，而是先进线程安全队列，再由游戏线程做 JSON 校验、时间排序和插值。骨骼通道进入 Pose Snapshot，Root Motion 交给 CharacterMovement，表情标量映射到 Morph Target。系统还处理超时回退、断线重连、异常帧和监控。当前四个表情通道是确定性测试波形，不冒充语音模型输出，但接口已经能直接承接组里的语音驱动数字人结果。

## 游戏客户端岗位版

### 简历条目

**MotionBridge UE｜C++ 动画与实时网络客户端 Demo**

- 基于 UE 5.6 C++ 构建可复用 ActorComponent，拆分网络接收、帧缓冲、动画消费、Foot IK、Morph 驱动和状态 UI 职责。
- 使用游戏线程边界、弱 UObject 引用、有界队列与生命周期清理，避免网络回调修改/持有正在销毁的 Actor。
- 实现第三人称角色自动冒烟测试，覆盖 Enhanced Input 配置、相机、移动、跳跃、落地和 AnimInstance。
- 使用 49 项 Python 测试、16 个 C++ 实验程序及 UE 命令行 PASS/FAIL 日志完成回归验收。

### 60 秒讲解

从客户端角度，这个项目重点不是单个动画效果，而是把实时功能拆成可维护的 UE 模块。接收组件负责协议和缓冲，WebSocket/UDP 组件只负责传输，AnimInstance 消费姿势，CharacterMovement 消费 root，Foot IK 和 Morph Driver 分别做后处理，HUD 只观察状态。线程回调只入队，所有 UObject 修改放在游戏线程。为了避免“看起来能跑但无法回归”，我还做了第三人称移动/跳跃冒烟测试、网络重连测试以及统一验收脚本。

## 5 分钟讲解结构

1. 30 秒：问题与目标——把离线/实时人体动画可靠送进 UE。
2. 60 秒：离线数据——BVH 层级、通道顺序、FK 与数值验证。
3. 60 秒：角色适配——IK Retargeter、参考姿势、Root Motion 与胶囊。
4. 60 秒：运行时——UDP/WebSocket、线程边界、有界缓冲、插值和回退。
5. 45 秒：质量——Foot IK、双接触点、斜坡法线、Before/After。
6. 30 秒：表情与监控——标量通道、Morph、UMG、延迟与质量统计。
7. 15 秒：边界——未自研重定向求解器，未实现语音模型，数据是同机测试。

## 15 分钟深讲结构

- 用一张架构图先讲离线链路与实时链路如何共用姿势语义。
- 展开 `World = ParentWorld * Local`、通道旋转顺序和 FK 验证。
- 展开 Root Motion 拆分：地面根、局部骨盆、逆根旋转表达残差。
- 展开 UE 消费：Pose Snapshot、CharacterMovement、避免 root 双重消费。
- 展开实时缓冲：时间戳、乱序插入、二分采样、插值、播放延迟和硬重同步。
- 展开线程安全：网络回调为什么不修改 Actor、队列何时清空、销毁时如何解绑。
- 展开 Foot IK：双射线、支撑状态、骨盆、Two Bone IK、法线旋转与限制。
- 展开验收数据、失败版本如何定位，以及哪些结果只能说明本机回环。

## 高频追问的诚实回答

### 哪些部分用了 AI？

工程脚手架、大量 C++/Python 实现和自动化脚本由 AI 协助生成与修改。我负责目标选择、逐段理解、视觉问题反馈、技术取舍确认和最终验收。投递前我会确保能够脱离 AI 解释协议、线程边界、缓冲、Root Motion、Foot IK 和关键代码。

### 你有没有自己实现重定向算法？

没有。跨骨架映射使用 UE IK Retargeter。我自己实现并验证的是 BVH/FK、Root Motion 数据处理、运行时传输缓冲、Foot IK 与表情通道驱动。

### 这是语音驱动数字人吗？

不是模型部分。当前上游是确定性实时数据服务，UE 侧已经具备接收骨骼与表情标量、平滑、恢复和监控的能力。未来可把组内语音驱动模型的输出适配到同一协议。

### 为什么同时有 UDP 和 WebSocket？

UDP 用于理解低延迟、允许丢包的连续姿势流；WebSocket 提供浏览器/服务端生态更方便的可靠双向连接。两者只替换传输层，共用解析、缓冲和动画消费层。

### 最大的技术问题是什么？

不是“把动画播出来”，而是明确每层的坐标和所有权：哪些变换属于骨盆、哪些属于角色根；网络线程只拥有字节，游戏线程才拥有 UObject；IK 输入不能把上一帧输出再次当原始姿势。很多视觉错误都来自这三类边界被混淆。
